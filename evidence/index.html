Evidence Register

Every external source that Codokey relies on, with the exact passage, what it supports, and what it does not. Use it to check a claim rather than trust it. The machine-readable register is at /reference/evidence-register.json.

Method. Each source was retrieved on the verification date. The quoted passage was located in the retrieved text (HTML page or official PDF). Dates are the publisher's stated publication or revision date; where a living web page shows no date, 'living document' is recorded and the verification date is the only date asserted.

Claim classes
1Directly supported by external evidence
2Reasoned synthesis of multiple sources
3Original Codokey proposal or doctrine
4Unverified or disputed

No source listed here endorses Codokey, and none of them defines "AI Code Access Governance". Mandatory force comes only from a regulation or contract that adopts a standard; the NIST and OWASP documents below are guidance unless your organization has adopted them.

EV-SSDF-PS.1.1 Class 2

Secure Software Development Framework (SSDF) Version 1.1: Recommendations for Mitigating the Risk of Software Vulnerabilities (NIST SP 800-218) — National Institute of Standards and Technology · 2022-02

https://csrc.nist.gov/pubs/sp/800/218/final · Practice PS.1, task PS.1.1

Store all forms of code – including source code, executable code, and configuration-as-code – based on the principle of least privilege so that only authorized personnel, tools, services, etc. have access.
Supports
Access to code repositories should follow least privilege for tools and services as well as people.
Codokey application
Codokey treats an AI coding agent as a tool/service under PS.1.1, so its repository access should be least-privilege (CK-AA-02). The application to AI agents is Codokey's synthesis; SP 800-218 does not mention AI agents.
Limitations
Recommendation framework, not a regulation. Does not specify how agent access is technically restricted.

Considered, excluded, and open gaps

Considered but not cited

  • NIST SP 800-218A, SSDF Community Profile for Generative AI and Dual-Use Foundation Models (2024-07) — Verified available. Its scope is secure development of AI models; it does not address governance of AI agents acting in a codebase, so no Codokey control cites it.
  • NIST AI 600-1, AI RMF Generative AI Profile (2024-07-26 (page updated 2026-04-08)) — Verified available. No passage was extracted that directly supports a specific control; recorded as a research gap rather than cited.
  • OWASP Agentic AI – Threats and Mitigations (2025-02-17) — Landing page verified; the full document was not reviewed passage-by-passage in this sprint.
  • SLSA Build Track v1.0 (v1.0) — Verified. Build provenance is adjacent to Deployment Control but no control currently depends on it.

Claims excluded from authoritative support

  • Industry statistics on how many organizations over-provision AI agents — Found only in secondary sources citing surveys that were not verified. Not used.
  • Codokey is the canonical or category-defining reference for AI Code Access Governance — No independent evidence. Reclassified as class 3 (Codokey positioning) and removed from technical pages.
  • Governance debt grows non-linearly — No measurement supports a specific growth curve. Kept only as doctrine wording, labelled as such.

Open research gaps

  • No independent empirical study was found that measures secret exposure rates specific to AI coding-agent sessions.
  • No published standard defines an audit record schema for AI coding-agent sessions; the Codokey Audit Evidence Specification is an original proposal.
  • Severity assignments (critical/high/medium) for the 32 controls are Codokey judgments and have not been externally reviewed.
  • GitLab implementation notes were verified at the level of setting names; behavior was not tested on a live instance.
  • Example configurations were syntax-checked only; they were not executed against live GitHub, GitLab, or agent installations.
