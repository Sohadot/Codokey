Preamble
Sovereignty begins at the access boundary.

Codokey is not a product. It is founding doctrine for AI Code Access Governance — the discipline of governing what AI agents, AI-touched code, and agentic workflows can access, expose, change, and move toward production.

AI agents did not merely accelerate code writing. They shifted software governance from reviewing authored code to defining machine-access authority before execution. Governance models built for human authorship cannot govern machine-speed access without redefining where sovereignty begins.

AI agents are not simply faster developers. They create a new access layer — one that operates before code review, before deployment gates, before any human observes the change. Human review after agent access is not enough to govern what the agent was allowed to see.

You cannot govern what you cannot define.
Codokey defines the boundary between code, keys, agents, and authority.

The First Law
Definition precedes audit.

The first law of agentic software governance is definition. Undefined authority cannot be audited, bounded, trusted, or safely delegated.

Definition is the first act of governance. It is not documentation. It is the act that makes all subsequent governance possible — the act that creates a boundary that can be enforced, an authority that can be revoked, a posture that can be assessed.

An organization that has not defined what an agent may see, which secrets are excluded, which authority paths are forbidden, and what audit memory must capture — has no governance posture to assess. It has only incident response waiting to happen.

The Problem
The governance gap is a failure of definition.

Before AI agents, governance anchored on human review — slow, visible, sequential. Now code moves at machine speed, often before any human observes the change.

Post-facto review cannot govern pre-session access. When an agent has already read the repository, encountered environment variables, prepared a pull request — governance is retrospective. In systems that move at machine speed, retrospective governance is a non-traceable breach waiting to be discovered.

Human review after agent access is not enough to govern what the agent was allowed to see. Code review asks what changed. It cannot reconstruct what was in scope before the change existed.

Governance must move upstream from code review to access definition — before the agent session begins, not after it completes. Operational model: Codokey Protocol v1.0.

The Codokey Position
Governance is the permission structure for safe machine-speed development.

Governance is not the brake. It is the permission structure that lets AI agents move faster safely — within defined secrets boundaries, scoped agent authority, explicit review gates, and reconstructable audit memory.

The ungoverned organization slows down after every incident. The governed organization moves faster because boundaries are already defined.

Five Founding Principles
The doctrine that governs Codokey.
01
Define before you deploy
Access boundaries before repository scope. Governance after agent execution is incident response — not governance.
02
Secrets are not code
Credentials and environment variables are a separate layer. Every agent evaluated against the secrets boundary independently of code access.
03
Autonomy requires authority definition
Autonomous is not ungoverned. Undefined authority is a security gap — not a feature of agentic development.
04
Governance debt compounds
Every unscoped session creates dependencies. See cost of undefined agent authority.
05
Vendor-agnostic by design
Tools change. Access boundaries do not. Codokey follows risk logic, not any vendor roadmap.
