Layer 06 · Accountability Layer · Reference specification

Audit Memory

Can you reconstruct what the agent could reach, what it did, who authorized it, and what was exposed?

Version
Protocol v1.1 · 2026-11-13
Scorecard controls
6 (3 critical)
Status
Codokey reference specification — not externally reviewed

Security objective

Retain enough tamper-protected, correlated records to answer, after the fact, the reconstruction questions defined in the Audit Evidence Specification — for every agent session.

Boundary governed

The evidentiary boundary between events that happened and records the organization can produce about them, outside the control of the actors being recorded.

Failure scenarios

Uncorrelated logs
Platform audit events show a bot pushed a branch; the agent's session log shows commands; nothing links the two, so scope and delegation cannot be reconstructed.
Retention shortfall
An exposure is discovered after the platform's audit-log window has passed; the session that read the secret is no longer on record.
Self-editable records
Logs are written to a location the agent identity can modify or delete.

Applicable agent capabilities

All agent classes that act on repositories; the record set expands with capability (tool calls, external requests, deployments).

Platform-neutral principles

  • Every record carries a session identifier that links platform events, agent logs, and approvals.
  • Scope at session start is recorded, not only actions taken: exposure analysis needs to know what was readable.
  • Records live outside the reach of the identities they describe.

Implementation examples

Examples show one way to implement a control on a specific platform. They are not universally secure configurations; adapt and test them in your environment.

Known limitations

  • Vendor agent logs vary in content and export options; some fields may not be available.
  • Logging what was readable (scope) is often harder than logging what was done; the specification marks which fields are commonly unavailable.
  • Records support accountability; they do not prevent incidents.

Remediation path

  1. Log agent actions with identity, delegating human, time, target, outcome (CK-AM-01).
  2. Store logs outside agent reach with retention lock (CK-AM-02).
  3. Export logs where platform retention is shorter than required (CK-AM-03).
  4. Exercise the secret-exposure runbook (CK-AM-04).
  5. Run Reference Case D against an export of one real session (with secrets removed).
