Layer 01 · Provenance Layer · Reference specification

Code Origin

Who — or what — produced this change, and on whose behalf?

Version
Protocol v1.1 · 2026-11-12
Scorecard controls
4 (1 critical)
Status
Codokey reference specification — not externally reviewed

Security objective

Make every change attributable to the identity that produced it (human, agent, or both) and to the human who delegated the work, so review obligations and audit reconstruction can be applied to the right actor.

Boundary governed

The boundary between an authenticated identity and the changes recorded under it in version control. It is crossed whenever an agent commits, pushes, or opens a pull request.

Failure scenarios

Shared-credential attribution loss
An agent runs with a developer's personal access token. Its commits appear under the developer's name; reviewers apply the obligations for a human-authored change and audit logs cannot separate the two actors.
Silent assistance
A large AI-assisted change is merged with no marker. Later, an incident review cannot establish which code paths were generated or what review they received.
Delegation gap
An agent identity is distinct, but nothing records which human asked it to act, so accountability stops at a bot account.

Applicable agent capabilities

Applies to task agents, MCP-connected agents, and autonomous agents that write commits or open pull requests. Suggestion-only agents (inline completion accepted by a human) are attributed to the human; record their use through the disclosure policy (CK-OR-03) rather than per-commit identity.

Platform-neutral principles

  • An agent never acts under a credential that also represents a person.
  • Attribution has two parts: the acting identity and the delegating human.
  • Disclosure must be machine-readable; free-text mentions in PR descriptions are not queryable evidence.

Implementation examples

Examples show one way to implement a control on a specific platform. They are not universally secure configurations; adapt and test them in your environment.

Known limitations

  • Git author and committer fields are self-asserted. Attribution is reliable only when tied to the authenticated identity that pushed (platform audit events) or to signed commits.
  • There is no industry-standard trailer for AI involvement; the convention below is an example, not a standard.
  • Assistance in an editor (accepted suggestions) is generally not detectable after the fact; policy disclosure is the realistic control.

Remediation path

  1. Provision a dedicated app/bot identity per agent integration (CK-OR-02).
  2. Adopt a commit-trailer or label convention and enforce it in the agent integration (CK-OR-01).
  3. Record the delegating human in the trailer or session log (feeds CK-AM-01).
  4. Publish the disclosure and review obligation in the SDLC policy (CK-OR-03).
