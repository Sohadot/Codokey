Codokey Protocol v1.1 / Layer 05

Layer 05 · Authority Layer · Reference specification

Deployment Control

Can an agent-produced change reach production, and who authorizes that step?

Version
Protocol v1.1 · 2026-11-12
Scorecard controls
5 (3 critical)
Status
Codokey reference specification — not externally reviewed

Security objective

Separate the authority to propose and merge code from the authority to release it, so that production deployment always passes a human approval that the triggering identity cannot grant itself, and production credentials are released only after that approval.

Boundary governed

The release boundary between a trusted branch and production systems, including the credentials that deployment jobs use.

Failure scenarios

Merge-equals-deploy
A pipeline deploys every merge to production automatically; once an agent change is merged, no further human decision exists.
Agent as deployer
An agent identity is listed among identities allowed to deploy to production or can trigger and approve the same deployment.
Credential pre-release
Production secrets are available to every job in the pipeline, including jobs that run on unreviewed agent branches.

Applicable agent capabilities

Autonomous and pipeline-integrated agents; also any agent whose merged changes trigger continuous deployment.

Platform-neutral principles

  • Automation and autonomy are different: automated deployment is acceptable when a human has authorized the release.
  • Production credentials are released after, and because of, approval.
  • The identity that triggers a deployment cannot approve it.

Implementation examples

Examples show one way to implement a control on a specific platform. They are not universally secure configurations; adapt and test them in your environment.

Known limitations

  • Some platforms restrict deployment-approval features by plan or repository visibility.
  • Emergency paths (hotfixes, break-glass) need their own recorded authorization; this layer does not define them.
  • Supply-chain integrity of the deployed artifact (build provenance) is adjacent and not covered by these controls.

Remediation path

  1. Gate production deployments on human approval with self-review prevented (CK-DC-01).
  2. Scope production secrets to the protected environment (CK-DC-02).
  3. Make secret scanning a required pipeline step (CK-DC-03).
  4. Route IaC and pipeline changes to infrastructure owners (CK-DC-05).
