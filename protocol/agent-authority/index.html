Agent Authority

What is the agent permitted to read, change, call, and execute — and is that the minimum the task needs?

Version
Protocol v1.1 · 2026-11-13
Scorecard controls
6 (4 critical)
Status
Codokey reference specification — not externally reviewed

Security objective

Bound each agent's authority to the task: specific repositories, specific permissions, specific tools, for a limited time, with authorization enforced by the systems the agent calls rather than by the agent's own judgment.

Boundary governed

The agent authority surface: the union of repository permissions, tool and MCP connections, network reach, and command execution granted to an agent identity.

Failure scenarios

Organization-wide token for a one-repository task
An agent installed with access to all repositories can read and push to repositories unrelated to its task; a prompt injection in one repository can act on another.
Open-ended tools
An agent is given a shell and broad network access when it only needs to edit files and open a pull request.
Token passthrough
An MCP server forwards the client's token to a downstream API without validating audience, extending the agent's reach beyond the approved scope.

Applicable agent capabilities

All agent classes. The required depth of control scales with capability: suggestion (read open file) < review (read + comment) < task (read + branch + PR) < MCP-connected (external tools) < autonomous (multi-step, deployment-adjacent).

Platform-neutral principles

  • Scope is declared before the agent runs and compared with what is actually granted.
  • Authorization is enforced downstream (permissions, protection rules), never delegated to the model.
  • Least agency: do not grant autonomy or tools the task does not need.

Implementation examples

Examples show one way to implement a control on a specific platform. They are not universally secure configurations; adapt and test them in your environment.

Known limitations

  • Platform permission models differ; a "read-only" grant on one platform may include metadata or issue access on another.
  • Command execution makes static scope analysis incomplete: an agent with a shell can reach anything the host can.
  • Short-lived tokens limit exposure duration, not misuse during their lifetime.

Remediation path

  1. Write an access policy entry per agent (CK-AA-01).
  2. Replace "all repositories" installations with explicit lists (CK-AA-05).
  3. Diff granted vs. required permissions and remove the excess (CK-AA-02) — Reference Case B automates this for declared grants.
  4. Inventory MCP/tool servers and reject token passthrough (CK-AA-03).
