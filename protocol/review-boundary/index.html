Layer 04 · Human Gate Layer · Reference specification

Review Boundary

Which human must approve before an agent's change becomes part of the protected codebase — and can that gate be skipped?

Version
Protocol v1.1 · 2026-11-13
Scorecard controls
5 (3 critical)
Status
Codokey reference specification — not externally reviewed

Security objective

Ensure agent-generated changes reach protected branches only after approval by a human who is independent of both the agent and the person who requested the change, with stricter routing for security-sensitive paths.

Boundary governed

The merge boundary between a proposed change (branch or pull request) and a protected branch that downstream builds and deployments trust.

Failure scenarios

Requester self-approval
A developer asks an agent to write a change and then approves the agent's pull request. One person has both requested and approved; the review requirement is satisfied in form only.
Administrator bypass
Branch protection exists but, by default on some platforms, does not apply to administrators; an admin-scoped automation merges without review.
Sensitive path drift
An agent edits a CI workflow or deployment manifest inside a large refactor; the general reviewer does not notice the authority change.

Applicable agent capabilities

Task, MCP-connected, and autonomous agents that open pull requests or push branches. Code-review agents may assist reviewers but do not count as an approving human.

Platform-neutral principles

  • Approval must come from a human independent of the agent and of the requester.
  • Approval applies to the latest pushed revision, not an earlier one.
  • Gates are enforced by platform settings that also bind administrators.

Implementation examples

Examples show one way to implement a control on a specific platform. They are not universally secure configurations; adapt and test them in your environment.

Known limitations

  • Independent approval reduces risk but does not guarantee review quality; large agent-generated diffs strain reviewers.
  • Platform defaults and plan tiers change; verify settings by export, not memory.
  • An AI code-review agent's approval should not be counted toward required approvals.

Remediation path

  1. Require independent approval and approval of the latest push (CK-RB-01).
  2. Apply rules to administrators and remove standing bypass (CK-RB-04).
  3. Route secret, CI, and deployment paths to owners (CK-RB-02).
  4. Use the AI-generated PR review checklist in the Reference Kit (CK-RB-03).
  5. Run Reference Case C against an export of your protection settings.
