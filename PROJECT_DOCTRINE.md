# Project Doctrine

**Version:** 1.1  
**Date:** 2026-06-01

Operating principles for the Codokey.com repository and reference infrastructure.

## 1. Reference Over Product

Every page, document, and interaction must position Codokey as a reference model. Never imply a working security tool exists unless one actually does.

## 2. Sovereign Language

Use institutional, precise, sovereign language. Avoid generic SaaS marketing tone, blog-style casualness, and engagement bait.

## 3. Governance Console Aesthetic

The site must feel like a code-governance console — diff review, protocol files, agent permission windows, terminal audit, reference documentation. Not a generic landing page.

## 4. Static and Durable

No backend. No newsletter dependency. No broken links. No placeholder pages. GitHub Pages compatible. Every asset must survive without external services.

## 5. Define Before Deploy

Content boundaries must be established before pages go live. Every page requires unique title, meta description, canonical, Open Graph, Twitter card, internal links, and footer.

## 6. Vendor Agnostic

The protocol follows risk management logic, not any single vendor roadmap. Tools change. Access boundaries do not.

## 7. Governance Debt Awareness

Every unscoped content decision creates maintenance debt. Document decisions. Maintain quality gates. Review quarterly.

## 8. No False Authority

The scorecard is a self-assessment reference model — not formal certification. State this clearly and consistently.

## 9. Strategic Restraint

Monetization, partnerships, and inquiries use restrained institutional language. No urgency marketing. No fake scarcity.

## 10. Internal Linking as Architecture

Strong internal linking is not SEO trickery — it is how reference infrastructure works. Every page connects to the protocol layers it implements.

## 11. Category Language Authority

Every future Codokey page, document, visual layer, and tool must reinforce Codokey as **the category language of AI Code Access Governance**.

- No generic AI coding content
- No generic cybersecurity blog content
- No shallow affiliate or SEO pages
- No product claims unless the product exists

If a piece of content does not strengthen category authority, it does not ship.
