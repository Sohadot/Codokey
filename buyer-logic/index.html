Strategic Inevitability
Who needs the category — and what they lose by waiting.

Codokey is category-defining doctrine — not a deployed security product. For each buyer below: what you gain from owning or citing the reference model, what you risk losing if you ignore the category, and why this discipline matters specifically to your position in the stack.

Category 01
AI Coding Platforms
Copilot, Cursor, Claude Code, and emerging agent platforms sit at the center of the authority surface they create.
Gain: vendor-neutral enterprise trust language for agent autonomy — charter, protocol, and permission taxonomy customers can cite in procurement and governance reviews.
Loss: losing the clearest enterprise trust language for agent autonomy — forcing every enterprise conversation to rebuild category vocabulary while a competitor cites Codokey first.
Why this buyer: platforms create the agent authority layer; they must own or align with the language that defines how enterprises trust it.
Category 02
DevSecOps Companies
Pipeline security, SAST, and CI/CD gates operate where code already exists — downstream of the agent session.
Gain: upstream positioning — map controls to the six protocol layers and own the question of what the agent accessed before code entered the pipeline.
Loss: staying downstream scanners while agent access governance becomes the upstream question — permanently positioned after the authority boundary is defined elsewhere.
Why this buyer: DevSecOps owns the path to production; agent access is the new entry point that path must account for.
Category 03
Secrets Management Companies
Vault and secrets managers protect credentials in storage — not in IDE agent read context during live sessions.
Gain: the agent-side secrets boundary — eight credential classes, pre-session governance rule, vocabulary for the fastest-growing exposure vector.
Loss: missing the agent-side secrets boundary — leaving the fastest-growing attack surface undefined in product narrative and enterprise policy.
Why this buyer: secrets governance splits between storage and session; agents operate in the session layer storage products cannot see.
Category 04
Git & Developer Platforms
GitHub, GitLab, and Bitbucket are the repository trust boundary — where agent scope, PATs, and deploy keys meet code.
Gain: agent permission architecture, forbidden zones, and repository trust boundary language for platform governance extensions.
Loss: letting competitors define repository trust boundaries for agentic development — while agent scope and deploy authority become someone else's category story.
Why this buyer: the platform is the trust boundary layer; AI agents broke permission models built for human developers.
Category 05
AI Governance & Compliance Teams
Enterprise compliance needs definitional infrastructure — not another dashboard claiming to govern AI without code-access precision.
Gain: audit-ready reference documentation — charter, protocol, scorecard — mappable to control frameworks with engineering-grade vocabulary.
Loss: relying on generic AI governance while code access becomes a specialized control surface — without language precise enough for engineering accountability.
Why this buyer: compliance must govern what agents access, not only what models say — code access is a distinct control surface.
